1. System Overview

The Knowledge Base System is an advanced document management and retrieval platform that leverages artificial intelligence to provide accurate, contextual answers from your document repositories. This system combines state-of-the-art natural language processing techniques with vector embeddings to create an intelligent question-answering solution specifically designed for educational content management.

Key Features

  • User-Based Access Control: Automatic binding of customer and organization based on login credentials
  • Multi-Level Knowledge Bases: Support for both Book Level and Study Level knowledge organization
  • Intelligent Document Processing: Automatically processes and indexes documents from multiple formats
  • Study LO Management: Specialized system for managing learning objectives in CSV format
  • Agent Configuration: Configurable agents for retrieval, compliance, match generation, and assessment
  • Advanced Retrieval: Multiple retrieval strategies including MMR, Similarity, and Hybrid approaches
  • Customizable Settings: Fine-tune system parameters to match your specific requirements

System Architecture

The system operates through a multi-stage pipeline designed for educational content management:

  1. User Authentication: Automatic binding of user to customer and organization
  2. Document Ingestion: Upload and validate documents in supported formats
  3. Knowledge Base Creation: Create Book Level and Study Level knowledge bases
  4. Study LO Management: Upload and manage learning objectives
  5. Preprocessing: Clean and structure document content
  6. Chunking: Split documents into optimally-sized segments
  7. Embedding Generation: Convert text chunks into vector representations
  8. Vector Storage: Store embeddings in high-performance databases
  9. Query Processing: Enhance and execute user queries
  10. Response Generation: Generate accurate answers using retrieved context

2. User Authentication & Auto-Binding

Purpose

The authentication system automatically binds users to their respective customer and organization based on login credentials. This ensures proper data isolation, access control, and organizational hierarchy within the knowledge base system.

How It Works

  1. User logs in with username and password credentials
  2. System validates credentials against the central database
  3. Upon successful authentication, the system automatically retrieves and binds:
    • Customer information associated with the user
    • Organization code linked to the user's account
  4. User is redirected to the dashboard with pre-bound customer and organization

Dashboard Interface Components

Select Customer Card

Displays the automatically bound customer information. Users cannot select other customers as this is determined by their login credentials.

Select Organization Card

Shows the automatically bound organization code. Users cannot select other organizations as this is determined by their account settings.

Apps Details Card

This is the only configurable component where users can select application details from a dropdown menu. The available apps are filtered based on the user's bound organization.

Security and Access Control

Important: The automatic binding ensures data security and prevents unauthorized access to other customers' or organizations' knowledge bases. Users can only access and manage knowledge bases within their assigned organizational scope.

5. Processing Settings

5.1 Retrieval Strategy

The retrieval strategy determines how the system identifies and selects relevant document chunks when processing user queries. The system offers three distinct strategies:

Maximum Marginal Relevance (MMR)

Overview

MMR balances relevance and diversity to provide comprehensive yet non-redundant information. This algorithm iteratively selects documents that are both relevant to the query and dissimilar to already selected documents.

How It Works

  1. Calculate relevance scores for all documents
  2. Select the most relevant document first
  3. For subsequent selections, balance relevance against diversity
  4. Penalize documents too similar to already selected ones
  5. Continue until k documents are selected
MMR Example

Query: "Tell me about different types of renewable energy"

Process: The system retrieves diverse chunks covering solar, wind, hydro, and geothermal energy rather than multiple similar chunks about just solar energy.

Result: Comprehensive coverage of multiple renewable energy types with minimal redundancy.

Available Embedding Models for MMR

  • text-embedding-ada-002
  • text-embedding-3-large

Similarity Search

Overview

Similarity search employs vector distance calculations to identify documents most semantically similar to the input query. This method calculates cosine similarity between the query embedding and all document embeddings in the vector store.

How It Works

  1. Query is converted to a vector embedding
  2. Cosine similarity is calculated against all document vectors
  3. Documents are ranked by similarity score
  4. Top-k most similar chunks are retrieved
Similarity Search Example

Query: "What is Newton's First Law of Motion?"

Process: The system retrieves the 5 most similar chunks that directly discuss Newton's First Law, inertia, and related concepts.

Result: Highly relevant chunks specifically about Newton's First Law from physics textbook sections.

Available Embedding Models for Similarity

  • all-MiniLM-L6-v2

Hybrid Cross Encoder (MMR + Similarity)

Overview

Hybrid approach combines the strengths of both MMR and Similarity search. It uses cross-encoder models to re-rank results from both strategies for optimal relevance and diversity.

How It Works

  1. Perform both MMR and Similarity searches independently
  2. Combine results from both strategies
  3. Use cross-encoder model to re-rank combined results
  4. Select top-k chunks based on cross-encoder scores
Hybrid Cross Encoder Example

Query: "Explain photosynthesis and its importance"

Process: System retrieves similar chunks about photosynthesis process (Similarity) and diverse chunks about importance, applications, and related concepts (MMR), then re-ranks them together.

Result: Balanced coverage with both detailed process information and broader contextual importance.

Available Embedding Models for Hybrid

  • text-embedding-ada-002
  • text-embedding-3-large
  • all-MiniLM-L6-v2

5.2 Number of k Values

Overview

The k parameter defines how many related chunks (contents) are retrieved for a query. For example, if k = 5, the system retrieves the top 5 most relevant chunks. Increasing k can improve coverage, but it can slow down processing because more content is included in the prompt/context sent to the model. Using a very low k can improve speed, but may reduce accuracy due to limited retrieved context.

Configuration

  • Default Value: 5
  • Minimum Value: 1
  • Maximum Value: 8
  • Step: 1

Recommendations

k Value Use Case Performance Impact
1-3 Simple queries, fast processing Fastest, limited coverage
4-6 Standard queries, balanced approach Optimal balance
7-8 Complex queries, maximum coverage Slower, comprehensive

5.3 Chunk Size

Overview

Chunk size determines how documents are segmented into smaller, processable units. The optimal chunk size depends on your content type and the granularity of information required.

Available Options

  • 20 tokens
  • 100 tokens
  • 250 tokens
  • 500 tokens
  • 1000 tokens

Selection Guidelines

Chunk Size Best For Example Use Cases
20 tokens Definitions, short facts Vocabulary terms, formula definitions
100 tokens Short explanations, FAQs Concept explanations, brief examples
250 tokens Standard paragraphs, procedures Method explanations, step-by-step guides
500 tokens Detailed explanations Case studies, detailed examples
1000 tokens Long-form content Chapter summaries, comprehensive topics

5.4 Overlap Percentage

Overview

Overlap creates redundancy between adjacent chunks to preserve contextual continuity across chunk boundaries. This prevents information loss when concepts span multiple chunks.

Available Options

  • 10%
  • 15%
  • 20%
  • 25%
  • 50%
Overlap Example: 20% Overlap

Original Text (simplified): "Photosynthesis is the process plants use to convert sunlight into energy. This process requires chlorophyll, which gives plants their green color. Photosynthesis occurs in chloroplasts and produces oxygen as a byproduct."

Without Overlap (0%):

  • Chunk 1: "Photosynthesis is the process plants use to convert sunlight into energy."
  • Chunk 2: "This process requires chlorophyll, which gives plants their green color."
  • Chunk 3: "Photosynthesis occurs in chloroplasts and produces oxygen as a byproduct."
  • Issue: Context break between chunks

With 20% Overlap:

  • Chunk 1: "Photosynthesis is the process plants use to convert sunlight into energy."
  • Chunk 2: "sunlight into energy. This process requires chlorophyll, which gives plants their green color."
  • Chunk 3: "green color. Photosynthesis occurs in chloroplasts and produces oxygen as a byproduct."
  • Benefit: Maintains context continuity across chunk boundaries

5.5 Chunking Strategy

Paragraph Strategy

Splits text at paragraph boundaries, preserving the natural flow of content.

Paragraph Chunking Example

Original Text:

"The water cycle describes how water evaporates from the Earth's surface, rises into the atmosphere, cools and condenses into rain or snow in clouds, and falls again to the surface as precipitation.

The water that falls on land collects in rivers and lakes, soil, and porous layers of rock, and much of it flows back into the oceans."

Resulting Chunks:

  • Chunk 1: Entire first paragraph about evaporation and condensation
  • Chunk 2: Entire second paragraph about collection and flow

Best For

  • Well-structured documents with clear paragraphs
  • Content where paragraph boundaries represent logical breaks
  • Narrative and explanatory content

Recursive Character Strategy

Recursively splits text based on character count, attempting to break at sentence boundaries when possible.

Recursive Character Chunking Example

Original Text (with chunk size = 100 characters):

"Mathematics is the study of numbers, shapes, and patterns. It is a fundamental discipline that underpins many sciences. Algebra, geometry, and calculus are major branches."

Resulting Chunks:

  • Chunk 1: "Mathematics is the study of numbers, shapes, and patterns. It is a fundamental"
  • Chunk 2: "discipline that underpins many sciences. Algebra, geometry, and calculus are"
  • Chunk 3: "major branches."

Best For

  • Documents without clear paragraph structure
  • Ensuring consistent chunk sizes
  • Technical documentation with mixed content types

7. Study Level Knowledge Base Creation

When to Create Study Level Knowledge Bases

Study Level knowledge bases should be created when you need focused, chapter-specific knowledge management. This is particularly useful for:

  • Individual chapter or unit management
  • Specialized content for specific learning objectives
  • Focused question generation for particular topics
  • Granular content control and updates

Creation Process

Step 1: Access Creation Interface

  1. From dashboard, click "Create New Knowledge Base"
  2. On the creation page, select "Study Level" from Knowledge Base Type

Step 2: Select Book

Choose the book from which you want to create a study-level knowledge base. Only books with existing Book Level knowledge bases are available.

Step 3: Select Study

Choose from the studies (learning objectives) uploaded during Study LO creation. The dropdown displays all Study LOs associated with the selected book.

Step 4: Upload Study Documents

Upload documents specific to the selected study. These should be focused on the particular chapter or learning objective.

Best Practice: Upload chapter-specific documents, focused exercises, or topic-specific materials rather than entire books.

Step 5: Configure Processing Settings

Follow the same Processing Settings configuration as Book Level knowledge bases, but consider:

  • Smaller Chunk Sizes: 100-250 tokens for focused content
  • Higher Overlap: 20-25% for context preservation in specialized content
  • Similarity Search: Often sufficient for focused study-level queries

Step 6: Create Knowledge Base

Click "Create Knowledge Base" and follow the same confirmation process as Book Level creation.

Benefits of Study Level Knowledge Bases

Benefit Description
Focused Retrieval More accurate results for chapter-specific queries
Targeted Updates Update specific chapters without affecting entire book
Specialized Configuration Optimize settings for specific content types
Granular Management Manage learning objectives independently

Delete Knowledge Base

Important: Deleting a knowledge base is a permanent action that cannot be undone. This operation removes:

  • Associated metadata and processing history
  • Any associated Study LOs (for Book Level deletion)

Knowledge Base Relationships

Hierarchical Structure

  • Book Level Knowledge Base: Parent container for Study Level knowledge bases
  • Study Level Knowledge Base: Child of Book Level, associated with specific Study LOs
  • Study LOs: Learning objectives linked to both Book and Study Level knowledge bases

Deletion Dependencies

Critical: Deleting a Book Level knowledge base does not automatically delete Study Level knowledge bases. Study Level knowledge bases remain available.

9. Guidelines Management

Accessing Guidelines Management

There are two ways to access guidelines management:

Option 1: From Dashboard

Click the green "Create New Guidelines" button on the Knowledge Bases card to create general guidelines that can be tagged to multiple knowledge bases.

Option 2: From Knowledge Base Actions

Click "Add Guidelines" in the Action column of a specific knowledge base to tag guidelines to that particular knowledge base.

Types of Guidelines

General Guidelines

Pre-created guidelines that can be tagged to multiple knowledge bases. These include:

  • Response Style Guidelines: Tone, format, and structure requirements
  • Compliance Guidelines: Regulatory and policy requirements
  • Educational Standards: Curriculum and assessment standards
  • Brand Guidelines: Organizational voice and terminology

Custom Guidelines

Guidelines created by users for specific knowledge bases. These can include:

  • Subject-specific terminology preferences
  • Assessment difficulty levels
  • Preferred explanation styles
  • Content inclusion/exclusion rules

Creating New Guidelines

Step-by-Step Process

  1. Click "Create New Guidelines" from dashboard
  2. Enter guideline name and description
  3. Select guideline type
  4. Enter guideline content using the text editor
  5. Optionally upload guideline document (PDF or TXT)
  6. Click "Save Guidelines"

Guideline Content Structure

# Response Guidelines for Science Content ## Tone and Style - Use formal academic tone - Explain concepts clearly for grade-level understanding - Include real-world examples when possible ## Content Requirements - Always cite scientific principles - Include relevant formulas and units - Explain cause-effect relationships ## Assessment Standards - Questions should test understanding, not memorization - Include multiple question types: MCQs, short answer, explanation - Difficulty distribution: 60% easy, 30% medium, 10% hard ## Compliance - Align with national curriculum standards - Include safety warnings for experiments - Ensure age-appropriate content

Tagging Guidelines to Knowledge Bases

From Knowledge Base Actions

  1. Click "Add Guidelines" in the Action column
  2. Browse available guidelines (General and previously created Custom)
  3. Select guidelines to tag to the knowledge base
  4. Click "Apply Guidelines"
  5. Guidelines are now active for that knowledge base

Guideline Priority System

  • Custom Guidelines: Highest priority, override general guidelines
  • Multiple Guidelines: Combined with AND logic
  • Conflicting Rules: Custom guidelines take precedence

Best Practice: Start with general guidelines for consistency across knowledge bases, then add custom guidelines for specific requirements. Review and update guidelines periodically as content and requirements evolve.

Guideline Impact on System Behavior

Response Generation

Guidelines influence how the system generates responses to queries by:

  • Controlling tone and style of answers
  • Ensuring compliance with standards
  • Maintaining consistency across similar queries
  • Enforcing content quality standards

Question Generation (AIG)

In the Advanced Item Generator application, guidelines affect:

  • Question difficulty levels
  • Question types and formats
  • Content coverage and distribution
  • Assessment standards compliance

Performance Optimization Tips

For Faster Processing

  • Use smaller chunk sizes (100-250 tokens)
  • Reduce overlap percentage (10-15%)
  • Use Similarity search instead of MMR or Hybrid
  • Select all-MiniLM-L6-v2 embedding model
  • Process documents in smaller batches

For Better Accuracy

  • Increase chunk size for context (250-500 tokens)
  • Use higher overlap (20-25%) for continuity
  • Select Hybrid Cross Encoder retrieval
  • Use text-embedding-3-large model
  • Ensure clear document structure

Conclusion

The Knowledge Base System provides a comprehensive, intelligent solution for educational content management and question answering. With its user-based access control, automatic customer/organization binding, and multi-level knowledge base structure (Book Level and Study Level), it offers a robust platform for managing educational content. The system's advanced features including multiple retrieval strategies (MMR, Similarity, Hybrid), configurable processing settings, Study LO management with agent configuration, and guidelines management ensure flexibility and adaptability to diverse educational needs.

By following the structured workflow—starting with Book Level knowledge base creation, proceeding to Study LO upload and agent configuration, and optionally creating Study Level knowledge bases—users can build a comprehensive knowledge ecosystem. The integration with Advanced Item Generator (AIG) enables automated question generation, making the system invaluable for educational content creators, teachers, and institutions.

Adherence to the best practices outlined in this documentation will help maintain optimal system performance, ensure high-quality outputs, and provide a seamless user experience. Regular maintenance, careful configuration, and systematic troubleshooting will ensure the knowledge base system continues to meet evolving educational needs effectively.

Detailed Workflow Explanation

Phase 1: Initial Setup & Navigation

  1. User Login: User logs into the system
  2. Navigate to AI Levate Apps: User accesses the AI Levate application
  3. Knowledge Base Icon: User clicks on the Knowledge Base icon in the left sidebar
  4. Dashboard: Knowledge Base Dashboard loads with three main options

Phase 2: Create New Guidelines (General Guidelines)

  1. Click Create New Guidelines: Opens the Add New Guideline page for General Guidelines
  2. Select Guideline Type: Choose from Guideline Type dropdown
  3. Select Guideline Subtype (Optional):
    • If selected, the subtype value auto-fills as the Guideline Name
    • If not selected, enter a custom name in the Guideline Name field
  4. Add Content: Either type text in "Guideline to Follow" field OR upload TXT/PDF file (MAX 5MB)
  5. Upload Guideline: Click "Upload Guideline" button
  6. View in All Guidelines Card: Uploaded general guidelines appear in the All Guidelines card
  7. Manage Guidelines: User can Edit or Delete general guidelines from this card

Phase 3: Book Level Knowledge Base Creation

  1. Select "Book Level" as knowledge base type
  2. System auto-fills organization based on login
  3. User selects App Details from dropdown
  4. Enter Book Name and Knowledge Base Name (with validations)
  5. Upload documents and optional cover image
  6. Configure processing settings:
    • Retrieval Strategy (MMR, Similarity, or Hybrid)
    • k value (1-8, default 5)
    • Chunk Size: 20, 100, 250, 500, 1000
    • Overlap Percentage: 10, 15, 20, 25, 50%
    • Chunking Strategy (Paragraph or Recursive)
    • Database Type (FAISS or ChromaDB)
    • Embedding Model (availability depends on retrieval strategy)
  7. Click "Create Knowledge Base" and confirm success

Phase 4: Study LO Creation

  1. Click "Create Study LO" from dashboard
  2. Select book from uploaded books
  3. Select App Details
  4. Configure agents (Retrieval and Assessment are default ON)
  5. Tag Agents Option: Available for customers who don't require Study LOs
  6. Upload Study LO document in CSV format
  7. Submit for processing

Phase 5: Study Level Knowledge Base Creation

  1. Select "Study Level" when creating new knowledge base
  2. Select book from uploaded books
  3. Select specific study from uploaded Study LOs
  4. Upload study-specific documents
  5. Configure processing settings (same as Book Level - connects to Processing Settings Configuration)
  6. Create the Study Level knowledge base

Phase 6: Knowledge Base Management

Each knowledge base has the following action buttons:

1. Edit Knowledge Base

  • Modify Processing Settings: Change previously selected configuration options
  • Add Additional Documents: Upload new PDF or other document types
  • Change Cover Image: Replace the existing cover image with a new one
  • All changes are saved and the KB is updated accordingly

2. Add Guidelines

User can choose between two options:

Option A: General Guideline (Tag Existing)

  • Display General Guidelines Card showing previously created general guidelines
  • View guideline names in the list
  • Select guidelines to tag to the KB
  • Preview guidelines by clicking the eye icon
  • Click "Tag Selected Guidelines" to apply them to the specific KB

Option B: New Guideline (KB-Specific)

  • Opens same form as "Create New Guidelines" but for KB-specific guidelines
  • Select Guideline Type from dropdown
  • Optionally select Guideline Subtype (auto-fills name) or enter custom name
  • Add content by typing text or uploading TXT/PDF (MAX 5MB)
  • These guidelines are specific to this knowledge base only (not general guidelines)

3. Chat with Document

  • Query the knowledge base using natural language
  • Get responses based on the indexed content

4. Tag Agents

  • Configure agent settings for the knowledge base
  • Particularly useful for customers who don't require Study LOs
  • Provides flexibility for different customer requirements

5. Delete Knowledge Base

  • Permanently remove the knowledge base
  • This action cannot be undone

Phase 7: AIG Integration

  1. Navigate to Advanced Item Generator (AIG) application
  2. System uses created knowledge bases for question generation
  3. Generate questions based on the indexed content

Key Decision Points

1. Knowledge Base Type Selection

Book Level: First-time creation, comprehensive content management for entire books

Study Level: Requires existing Book Level KB and Study LOs, focused on specific study materials

2. Retrieval Strategy Choice

Strategy Best For Embedding Models
MMR Diverse, non-redundant information retrieval text-embedding-ada-002
text-embedding-3-large
Similarity Direct, precise matching all-MiniLM-L6-v2
Hybrid Balanced approach combining multiple strategies All three models available

3. Guidelines Types

General Guidelines: Created via "Create New Guidelines" button, can be tagged to any knowledge base, stored in All Guidelines card, reusable across multiple KBs

KB-Specific Guidelines: Created when adding guidelines to a specific KB via "New Guideline" option, tied to that particular knowledge base only

4. Agent Configuration

In Study LO Creation: Tightly coupled - AI must require Study LOs and agent configuration

Tag Agents Action: For customers who don't require Study LOs, provides flexibility to configure agents separately

Important Notes:
  • Study Level knowledge bases require existing Book Level KB and Study LOs
  • Name validations apply to both Book Name and Knowledge Base Name
  • Embedding model availability depends on the selected retrieval strategy
  • Deleting a knowledge base is permanent and cannot be undone
  • General guidelines can be reused across multiple knowledge bases
  • KB-specific guidelines are tied to individual knowledge bases
  • Maximum file size for guideline documents is 5MB
  • Supported guideline file formats: TXT and PDF
  • Users can edit existing KBs to modify settings, add documents, or change cover images
  • Tag Agents option provides flexibility for customers without Study LO requirements
